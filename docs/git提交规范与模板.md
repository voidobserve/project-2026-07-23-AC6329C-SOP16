# Git 提交信息规范与模板

> 依据本仓库已有历史（`Initial commit` → `移植过来的旧版工程` → `2026-09-24-周四，存档` →
> `feat(led_strip): …` / `chore(git): …`）整理。**从现在起统一使用下面的 Conventional Commits 中文版**，
> 并在首行加**提交时间前缀**（`YYYY-MM-DD HH:MM`），方便按时间检索历史。

## 1. 基本格式

```
<YYYY-MM-DD HH:MM> <type>(<scope>): <一句话摘要，不加句号>

<正文：为什么改 / 改了什么 / 影响范围>

<页脚：编译验证、BREAKING CHANGE、关联单号>
```

首行示例：

```
2026-10-06 18:20 feat(led_strip): 新增跑动分组动画
```

| 位置 | 要求 |
| --- | --- |
| 时间前缀 | 提交时刻的本地时间，`YYYY-MM-DD HH:MM`，与 `type` 之间空一格；不加秒 |
| type | 小写英文，见 §3；一次提交只用一种 |
| scope | 模块/文件名，见 §4；确实跨模块时写主要那个 |
| 摘要 | 中文，动词开头（新增/修复/重构/调整/删除），**说完"做了什么"**，不写"提交代码"这类废话 |
| 正文 | 每行 `- ` 一条，讲清**为什么**改 + 关键参数/边界；一句话能说清时可省略 |
| 页脚 | 编译情况、接口破坏、关联需求号（时间已在首行，页脚不再重复） |

整行长度：含时间前缀一起控制在 **70 字符**以内（中文摘要部分 ≤ 25 字）。

## 2. 时间前缀与按时间查找

时间前缀是可被 `git log --grep` 搜到的纯文本，用来补「`git log` 默认不显示时间」的不便；
git 自带的 `%ad` / `%cd` 照样有效，两者互不冲突。

| 需求 | 命令 |
| --- | --- |
| 带时间看最近提交 | `git log -10 --pretty=format:'%h %ad %s' --date=format:'%Y-%m-%d %H:%M'` |
| 按信息里的日期搜 | `git log --oneline --grep='2026-10-06'` |
| 按区间看 | `git log --since='2026-10-01 00:00' --until='2026-10-07 23:59' --pretty=format:'%h %ad %s' --date=format:'%Y-%m-%d %H:%M'` |
| 查某天所有分支的提交 | `git log --all --grep='2026-10-06' --pretty=format:'%h %s'` |
| 设一个短别名（一次性） | `git config --global alias.lgd "log --pretty=format:'%h %ad %s' --date=format:'%Y-%m-%d %H:%M'"` |

设完别名后：`git lgd -20` 看最近 20 条（时间 + 内容），`git lgd --since=2026-10-01` 按区间过滤。

时间前缀使用规则：

1. 写**提交当时**的本地时间，如 `2026-10-06 18:20`；半小时内连续提交也照实写，便于区分。
2. 事后补提交旧改动时，写**实际操作时间**，不要倒填代码完成时间 —— 否则与 `%ad` 对不上，检索会误导。
3. `git commit --amend` / `rebase` 会刷新提交时间，若沿用旧信息，记得把首行时间一起改。
4. 跨零点提交按实际日期写；不写星期、不加秒。

## 3. type 取值

| type | 用途 |
| --- | --- |
| `feat` | 新功能、新动画、新指令支持 |
| `fix` | 修 Bug、修观感错误、修编译/链接问题 |
| `refactor` | 只改结构不改行为（拆文件、抽函数、去重复） |
| `perf` | 只优化性能（RAM/帧率/耗时） |
| `docs` | 只改 `docs/`、`README`、注释文档 |
| `chore` | 杂项：`.gitignore`、工程配置、版本号、存档 |
| `build` | 构建脚本、编译选项、`.cbp`/`Makefile`/`tasks.json` 调整 |
| `test` | 增加/修改测试或自检脚本 |
| `revert` | 回退某次提交 |
| `archive`（本仓库习惯，可选） | 每日存档，摘要写"当日存档（要点）"，日期由首行时间前缀承担 |

> 历史提交里的 `archive` 写法（如 `2026-09-24-周四，存档`）仍可用 `--grep='2026-09-24'` 搜到，不必回头改写。

## 4. scope 取值（本仓库常用）

| scope | 对应位置 |
| --- | --- |
| `led_strip` | `apps/user_app/led_strip/**`（场景层、动画、时序） |
| `ws2812fx` | `apps/user_app/ws2812-fx-lib/**` |
| `protocol` | `apps/user_app/protocol/**`、App 通信指令 |
| `app` | `apps/user_app/*.c`、`user_config.h`、线程/主流程 |
| `board` | `apps/spp_and_le/board/bd19/**`、板级配置 |
| `hw` | 硬件驱动层（`hardware/`、`one_wire/`、`rf24g_key/`） |
| `ble` / `audio` / `time` / `flash` | 对应模块目录 |
| `docs` | `docs/**` |
| `git` / `build` | 仓库与构建配置 |

## 5. 正文写法要求（本项目特有）

1. **参数一定写清**：默认值、取值域、边界含义，例如
   `byte7 = 每组灯数；0 或 > 灯带长度 → 整条一组`。
2. **协议相关**必须写字段位置与示例（如 `7F FF | mode | dir | speed | brightness | …`）。
3. **观感类改动**用"改前 → 改后"描述，例如
   `跑动：改前整条常亮 → 改后 ●●○○●● 逐位移位`。
4. **同步文档**：代码改动必须同步 `docs/`，在正文末尾单独一行写明
   `文档：docs/子动画参数与效果说明.md（§2.12 跑动）`。
5. **未验证的必须标注**：`未上机验证：动画观感需实测确认`。
6. 一次提交只做一件事。重构 + 行为改动尽量拆成两次；若必须合在一起，正文分段说明。
7. 正文里若引用了别的提交，写成 `revert d57146f`、`同 d57146f` 形式，便于回溯。

## 6. 页脚约定

```
编译：ac632n_spp_and_le（CodeBlocks，通过）/ 未编译
影响：无接口变更 / BREAKING CHANGE: <具体破坏点>
关联：无 / Refs: #12
文档：docs/xxx.md（已同步）
```

- **BREAKING CHANGE** 必须单独一行、全大写，并说明"谁需要改、怎么改"（App 端指令、上位机脚本等）。
- 编译情况务必真实：本项目约束"不调用工具编译"时，就写 `未编译`，不要写"通过"。
- 页脚不再写日期（首行已有时间前缀）；同一提交信息里的时间只出现一次，避免两处不一致。

## 7. 模板（直接复制）

### 7.1 新功能 feat

```
2026-10-06 18:20 feat(led_strip): 新增 XX 动画并接入 App 指令

- 背景：App 需要 XX 效果，原有 YY 模式改参数实现不了
- 新增 anim_xx()：参数 A 默认 3，可调范围 1~6；参数 B 0 表示按灯带长度自适应
- 场景层新增 led_strip_rgb_scene_get_xx()，动画只读场景、不直接解析协议
- 指令 0x0E 接入，字段布局 7F FF | 0E | dir | speed | brightness | bg | len | RGB…

编译：未编译
影响：无接口变更
文档：docs/子动画参数与效果说明.md（新增 §2.14）
```

### 7.2 修 Bug fix

```
2026-10-06 18:35 fix(led_strip): 修复开合动画整条闪烁

- 现象：leds_per_seg == 0 时整条灯带一起闪，没有流水开合
- 原因：步长按整段长度取整，每帧点亮整条；帧间隔又跟随 App 速度（最快 10ms）
- 改法：步长与帧间隔改为按灯带长度自适应（6 灯：133ms/帧，一次开合 800ms）
- 验证：6 灯 ●○→●● 逐点亮，闭合从尾部先灭

编译：未编译
影响：无接口变更
文档：docs/子动画参数与效果说明.md（同步 §2.11）
```

### 7.3 重构 refactor

```
2026-10-06 19:05 refactor(led_strip): 动画与协议解耦，抽出场景层

- 新增 led_strip_rgb_scene.[ch]：App 参数先落场景，动画只读场景
- 新增 led_strip_rgb_scene_anim.[ch]：全部动画集中，删除散落在 ws2812fx2.c 的旧动画
- 行为不变：模式表与各模式输出灯效与重构前一致

编译：未编译
影响：无接口变更
```

### 7.4 文档 docs

```
2026-10-06 19:30 docs: 补充子动画参数与效果说明

- 新增 §5 调速对照表：慢/快两端耗时与灯带长度的关系
- 补充 §6 6 灯实测预期，方便上机时逐条核对
```

### 7.5 仓库/工程配置 chore / build

```
2026-10-06 20:10 chore(git): .gitignore 改用通配覆盖编译产物，并取消跟踪 symbol_tbl.txt

- 补上 Makefile 构建目录 objs/（make ac6xxn_xxx 会生成，之前完全没忽略）
- CodeBlocks 的 obj/、*.depend、*.layout 改通配，换工程名/换 board 也不再漏
- symbol_tbl.txt 由 download.bat 每次编译重写，从索引移除（本地文件保留）
- 不使用 *.bin 宽通配：bd19loader.bin / cfg_tool.bin / p11_code.bin / rom.lst 是厂商自带文件
```

### 7.6 每日存档 archive（沿用历史习惯）

```
2026-10-06 20:40 archive: 当日存档（跑动/开合/堆积/流星观感调整）

- 本次改动：跑动按灯带长度分组、开合流速自适应、堆积节奏、流星拖尾对比度
- 协议：byte7 语义确认为"每组灯数"，0 与越界均按整条一组
- 状态：未上机验证
```

> 想保留 `${日期}-周${X}，存档` 的老写法也可以，首行时间前缀仍是必需的。

### 7.7 回退 revert

```
2026-10-06 21:00 revert(led_strip): 回退 "跑动改为 ●●○○●● 分组"

- 原因：现场观感与预期不符（每帧只有 2 红 1 青），需先定位再重做
- 本提交为 revert d57146f 中的跑动部分（commit: <hash>）
```

## 8. 本仓库注意事项

1. **首行时间前缀必须真实**：写提交当时的本地时间（如 `2026-10-06 18:20`），
   补提交旧内容时写实际操作时间；`--amend` / `rebase` 后若提交时间变了，记得同步改首行。
2. **PowerShell 下中文提交信息会乱码**：`git commit -m "中文"` 经 PowerShell 传参会变
   `鏀圭敤閫氶厤`。做法是先把信息写到临时文件（UTF-8，无 BOM），再
   `git commit -F <文件>`，提交后删掉临时文件。
3. **提交前先 `git status`**：确认没有编译产物混进来（`.gitignore` 已覆盖
   `obj/`、`objs/`、`cpu/*/tools/` 产物等）。若产物曾入库，忽略规则不会生效，需要
   `git rm --cached`。
4. **只提交源码和 `docs/`**：`agent/`、`.obsidian/`、编译产物一律不入库。
5. **不合并无关改动**：`README-additional.md` 之类的顺手改动，单独一次提交，别塞进功能提交里。
6. 提交信息里不要写真名/工号/机器路径等隐私信息；不要写"由 AI 生成"之类无意义内容。
7. 提交后想核对当天做了哪些提交：`git lgd --since=<当天 00:00>`（别名见 §2）。

## 9. 提交前自查清单

- [ ] 首行带了提交时间 `YYYY-MM-DD HH:MM`，且与实际提交时刻一致
- [ ] type / scope 正确，摘要说清了"做了什么"，整行（含时间前缀）≤ 70 字符
- [ ] 正文解释了"为什么改"，参数与边界写清（默认值、0 与越界的含义）
- [ ] 观感类改动写了"改前 → 改后"
- [ ] 代码改动已同步 `docs/`，并在正文里点名文件与章节
- [ ] 页脚写了真实编译情况；未验证项已注明
- [ ] 有接口/协议破坏时写了 `BREAKING CHANGE`
- [ ] `git status` 干净，没有编译产物
- [ ] 一次提交只讲一件事
