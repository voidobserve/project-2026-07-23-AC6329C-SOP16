# 幻彩灯「子动画」参数与效果说明

> 配套文档：[`重构说明-led_strip_rgb_scene.md`](./重构说明-led_strip_rgb_scene.md)（整体架构、数据流、模式表）
> 代码位置：`apps/user_app/led_strip/led_strip_rgb_scene_anim.c`（所有动画实现）、
> `led_strip_rgb_scene_schedule.c`（模式表 / 段参数）、`led_strip_rgb_scene.c`（参数换算）
>
> 本文逐个说明每个动画**用到哪些参数、状态放在哪、一帧里具体画成什么样、周期怎么算**，
> 以及调手感时该改哪个宏。改动画、加动画、排查「效果不对」时看这一篇即可。

## 0. 公共约定（所有动画都适用）

### 0.1 一帧是怎么跑起来的

```
10ms 定时任务  →  WS2812FX_service()
                     └─ 到时间了就调用  _seg->mode()   ← 就是我们写的动画函数
                        返回值 = 下一帧间隔(ms)（会被钳到 >= SPEED_MIN = 10ms）
                     └─ 有任一帧跑过就 WS2812FX_show() 刷屏
```

- 动画函数签名统一是 `u16 xxx(void)`，**只画一帧**，然后 `return` 下一帧间隔；
- 一帧里要把整条灯带该显示的内容画完（除了流星这类「增量画」的动画）；
- 灯珠下标统一用 `anim_led_index_of(led_pos)`（逻辑位置 → 实际灯珠，内部按方向换算），
  跑动集合因为子动画自带方向，用 `anim_led_index_of_dir(led_pos, reverse)`。

### 0.2 参数从哪里来（只读场景，不读 `fc_effect`）

| 参数 | 取值函数 | 说明 |
| --- | --- | --- |
| 段长度 | `_seg_len` | 本工程 = `LED_STRIP_RGB_NUMS` = **6 个灯** |
| 帧间隔 | `anim_frame_interval_ms()` | 就是段参数 `_seg->speed`（ms），由速度百分比换算 |
| 段大小（多少个灯为一组） | `anim_leds_per_seg()` | byte7 原值；**`0` 或 `> _seg_len` → `_seg_len`（整条为一组）**；其余 ≥ 1，上限 255 |
| 颜色数量 | `anim_color_count()` | 1 ~ `APP_MSG_COLOR_NUM_MAX`(8) |
| 第 i 个颜色 | `anim_pick_color(i)` | `colors[i % color_count]`，返回 `0xRRGGBB` |
| 底色 | `anim_background_color()` | app 下发的背景色（默认黑） |
| 方向 | `led_strip_rgb_scene_is_reverse()` | 0 正向 / 1 反向 |

速度 → 帧间隔的换算（`led_strip_rgb_scene.c`）：

| 速度百分比 | 0% | 50% | 100% |
| --- | --- | --- | --- |
| 帧间隔 | 500ms | 250ms | 钳到 `get_max_speed()` = **10ms** |

亮度 → WS2812FX 全局亮度：`percent*(255-25)/100 + 25`（最低 25，防止 app 调到 0 之后全黑）。

### 0.3 运行状态放在哪（**不要另开静态变量存“进度”**）

| 槽位 | 类型 | 谁在用 |
| --- | --- | --- |
| `_seg_rt->counter_mode_step` | u32 | 主进度/相位/帧计数（各动画含义见下文） |
| `_seg_rt->aux_param` | u8 | 配色偏移 / 颜色下标 / 子动画下标 / 加速剩余帧 |
| `_seg_rt->aux_param3` | u16 | 停留帧计数 / 随机位置 / 拍间隔 |
| `_seg_rt->aux_param2` | u8 | ❌ **不要用**：WS2812FX 的 `SET_FRAME / SET_CYCLE` 标志占着它 |

- `SET_CYCLE` 表示「这一帧刚好跑完一轮」（只做标记，不影响画面）；
- 只有「一个动画要存多个数组/结构」（星云、流星雨、频谱）时才用**文件静态变量**，
  并且必须在 `led_strip_rgb_scene_anim_reset()` 里复位（切模式时会被调用）。

### 0.4 分段排色规则（渐变 / 跳变 / 呼吸 / 堆积 / 跑动都用）

```
第 n 段（段大小 = leds_per_seg）用颜色池里的第 (n + color_offset) 个颜色（自动对颜色数量取模）
→ 段大小 = 1 且多色时，就是「每个灯一种颜色，循环排」
→ 段大小凑不满整条灯带时，剩下的灯珠接着下一段继续排色，不会留黑
   （例：6 灯 / 段大小 5 → 前 5 个灯用颜色 0，第 6 个灯用颜色 1）
```

> **堆积是例外**：`anim_accumulation_group_len()` 直接读 byte7 原值 ——
> `0` = 1 个灯一组（逐灯堆积）、`> 灯带长度` = 整条一组
> （其它动画里 `0` 是「整条为一组」；堆积若也这么算，就会变成整条灯带一起闪）。

## 2. 普通动画详解

### 2.1 静态色 0x01 — `anim_static`

| 项 | 内容 |
| --- | --- |
| 参数 | 颜色池第 0 个颜色 |
| 状态 | 无 |
| 效果 | 整条灯带铺第 0 个颜色 |
| 返回值 | **固定 1000ms**（画面不变，没必要每帧重画） |

### 2.2 渐变 0x02 — `anim_gradual`

| 项 | 内容 |
| --- | --- |
| 参数 | 段大小、颜色数量、颜色池 |
| 状态 | `step` = 渐变进度 0~255；`aux_param` = 配色偏移（多色时）；`aux_param3` = 只有一种颜色时的方向标志（0 = 本色在前，1 = 另一种颜色在前） |
| 内部宏 | `ANIM_FRAME_MS`(20) / `ANIM_GRADUAL_ROUND_SLOW_MS`(6000) / `ANIM_GRADUAL_ROUND_FAST_MS`(1200) / `ANIM_GRADUAL_WHITE`(0x00FFFFFF) / `ANIM_GRADUAL_BLACK`(0x000000) |

**一帧画什么**：第 n 段 = `blend(colors[n+偏移], colors[n+偏移+1], 进度)`
→ 每个段在「自己这一色」和「下一色」之间渐变，最后一种颜色会渐回第一种（颜色池是循环的）。

**只有一种颜色时**：颜色池凑不出「一对颜色」，所以**由代码补上「另一种颜色」，取一个和本色反差大的**：
本色不是黑色 → 补**黑色**（`ANIM_GRADUAL_BLACK` = `0x000000`），画面在「本色 ↔ 黑」之间渐变（熄灭式呼吸）；
本色是黑色 → 补**白色**（`ANIM_GRADUAL_WHITE` = `0x00FFFFFF`），画面在「黑 ↔ 白」之间渐变（否则全黑看不见）。
两轮之间起点/终点互换（`aux_param3` 只当方向标志：0 = 本色在前，1 = 另一种颜色在前）——
这一轮的结束色就是下一轮的起始色，所以**依然不跳色**（一轮 = 半个呼吸）。

**周期**：

```
进度 += anim_step_of_round(256, 一轮时长, 20ms)
进度到 255 → 进度归零 + 配色偏移 +1 + SET_CYCLE
一轮时长 = 6000 - (6000-1200)*速度/100      // 速度 0% = 6s，100% = 1.2s
```

> 配色偏移 +1 的瞬间，画面正好是「上一对的结束色 = 下一对的起始色」，所以**切换不跳色**。

**手感**：速度只改「一轮时长」；帧间隔固定 20ms，所以不会一帧一帧跳。
6 灯 / 段大小 1 / 3 色时：6 个段依次落在「红→绿、绿→蓝、蓝→红」三种渐变上（循环）。
6 灯 / 只有 1 色（例如红色）时：6 个灯同步在「红 ↔ 黑」之间来回渐变（两轮 = 一次呼吸）；
如果唯一那个颜色是黑色：6 个灯同步在「黑 ↔ 白」之间来回渐变。

### 2.3 跳变 0x03 — `anim_jump`

| 项 | 内容 |
| --- | --- |
| 参数 | 段大小、颜色数量、颜色池 |
| 状态 | `step` = 帧计数 0~3；`aux_param` = 配色偏移 |
| 帧间隔 | 速度换算（10~500ms） |

**效果**：整条按段排色（同 0.4 规则），**每 4 帧配色偏移 +1**
→ 同一个灯的颜色不断轮换，看起来就是「跳变」。

> 与呼吸的区别：呼吸的配色**按位置固定**、一轮结束不换色；跳变**每 4 帧换色**。

### 2.4 呼吸 0x04 — `anim_breath`

| 项 | 内容 |
| --- | --- |
| 参数 | 段大小、颜色数量、颜色池、底色 |
| 状态 | `step` = 呼吸进度 0~511 |
| 内部 | `anim_step_per_frame(512, anim_cycle_time_ms(6000, 1000))`，一轮时长 1s ~ 6s |

**效果**：0 → 255 → 0 的三角波当亮度包络，每段 = `blend(底色, colors[段号], 包络)`
→ 每个段在自己的底色和颜色之间来回呼吸；**配色按位置固定，一轮结束不换色**（只 `SET_CYCLE`）。

### 2.5 流水 0x05 — `anim_running_water`

| 项 | 内容 |
| --- | --- |
| 参数 | **只用颜色数量**（app 的段大小不参与，见下） |
| 状态 | `step` = 流动相位 |
| 内部宏 | `ANIM_COLOR_UNIT`(256) / `ANIM_WATER_ROUND_SLOW_MS`(6000) / `ANIM_WATER_ROUND_FAST_MS`(1500) |

**一帧画什么**：

```
一个「颜色循环」的总相位 = 颜色数量 * 256
第 i 个灯的相位 = i * 总相位 / 灯带长度        // 按灯串长度均分
相位随流动递减 → 相邻两色之间混色渐变 → 颜色循环沿灯带向末端流动
（例：6 灯 + 红蓝 = 红-红蓝-蓝-蓝红-红蓝-蓝）
```

> **不按 app 的段大小分段**：分段只由颜色数量决定，这样每种颜色分到的灯珠一定是均匀的
> （否则红只分到很少的灯）。
> 相位用**递减**（`phase + 总相位 - flow`）才会朝灯带末端流，用加法方向是反的。

### 2.6 堆积 0x06 — `anim_accumulation`

| 项 | 内容 |
| --- | --- |
| 参数 | **byte7 原值**（`0` = 1 个灯一组、`≥ 灯带长度` = 整条一组）、颜色数量、颜色池、底色 |
| 状态 | `step` = 已点亮灯数；`aux_param` = 当前颜色；`aux_param3` = 停留帧计数 |
| 内部 | `anim_accumulation_group_len()`（直接读 byte7 原值）、`ANIM_ACCUM_ROUND_SLOW_MS`(3000) / `..._FAST_MS`(900) / `..._FRAME_MS_MIN`(10) |

**节奏（点亮整条灯带的时长只由速度决定，跟灯带长度无关）**：

```
round_ms = 速度在 [3000ms(0%), 900ms(100%)] 之间插值   // 点亮整条灯带
steps    = ceil(灯带长度 / 一组灯数)                    // 一共要点几步（一步一组）
frame_ms = round_ms / steps（≥ 10ms）                  // 每帧点一组，作为动画返回值
点满后停留 steps 帧（= 一个 round_ms），再换下一种颜色
```

> 以前帧间隔直接跟 app 速度走（最快 10ms），6 灯 60ms 就点满了，看着就是「一下亮完」；
> 现在 6 灯最快 = 150ms 一组（900ms 点满、停 900ms，一轮约 1.8s）；长灯带 steps 变多、
> 帧间隔自动变小（下限 10ms），点亮整条仍是 900ms~3s。

**效果**：每帧往前点亮一组（一组 = byte7 个灯），点亮的灯用当前颜色，
没点亮的用底色；整条点满后停留一拍再换下一种颜色重新堆积（`SET_CYCLE`）。

```
byte7 = 0        → 1 个灯一组：逐灯堆积（6 灯 = 6 步）
byte7 ≥ 灯带长度 → 整条灯带一组（一步点完整条）
其它             → 取原值
```

> 以前 `byte7 = 0` 被当成「所有灯为同一组」，整条灯带一起亮、一起灭，看着就是整条灯带在闪，
> 所以堆积单独把 `0` 当成「1 个灯」。

### 2.7 星空 0x07 — `anim_starry_sky`

| 项 | 内容 |
| --- | --- |
| 参数 | 颜色数量、颜色池、底色 |
| 状态 | `step` = 帧计数 0~3；`aux_param` = 颜色下标；`aux_param3` = 随机位置 |
| 段选项 | **`FADE_XSLOW`**（唯一带 FADE 的动画） |
| 帧间隔 | 速度换算 |

**效果**：每 4 帧换一个随机位置、随机颜色，点亮那个灯；
每帧先 `WS2812FX_fade_out()` 让上一帧的亮点留下余晖（渐到 `_seg->colors[1]` = 黑，速率取 `FADE_XSLOW`）。
**刚进入这个模式的第一帧会先清屏**（`anim_take_first_frame()`），否则上一轮的余晖会残留很久。

### 2.8 星云 0x08 — `anim_nebula`

| 项 | 内容 |
| --- | --- |
| 参数 | 段大小（当「星空团」大小，再夹到「灯带长度/2」）、颜色数量、颜色池、底色 |
| 状态 | 文件静态：`anim_nebula_envelope/pos/color/step[]` + `count` + `inited` |

**效果**：

```
团大小 block_len = min(段大小, _seg_len/2)，至少 1
同时亮的团数    = _seg_len / block_len，夹到 ANIM_NEBULA_MAX(8)
每个团：位置随机、颜色随机（非黑）、包络步进 12~36
       亮度包络 0→255→0（共 ANIM_NEBULA_ENVELOPE_MAX = 510 步，步进越大闪得越快）
       包络走完一轮 → 换位置、换颜色重新开始
团内：中间最亮、两侧递减
每帧：先整条铺底色，再把各个团按亮度画上去 → 不会在灯带中间积出一块固定颜色
```

> 6 灯：段大小 1 → 6 个团（每颗灯一个团）；段大小 2 → 3 个团；段大小 ≥ 3 → 2 个团
> （团大小被夹到「灯带长度/2」= 3）。

### 2.9 流星 0x09 — `anim_meteor`

| 项 | 内容 |
| --- | --- |
| 参数 | 颜色数量、颜色池、底色 |
| 状态 | `step` = 帧计数；`aux_param` = 颜色下标；文件静态 `anim_meteor_rate_index` = 亮度档 |
| 内部 | 亮度表 `anim_meteor_rate[] = {100,70,45,30,20,15,10,7,5,4,3,2}`（**12 档**，%）、拖尾端点色 `anim_meteor_trail_colors()` |

**效果**：进入时先整条刷底色；之后每帧

```
整条平移一个灯（反向则往另一边推）
头部写一个像素，亮度取亮度表的下一档（100% → 70% → … → 2%）
12 档走完后头部写「底色」→ 流星尾部顺着灯带排出去
一轮 = (灯带长度 - 1) + 12*2 帧       // 6 灯 = 29 帧
```

**拖尾两端色**（`anim_meteor_trail_colors()`，决定了流星在什么底色上都看得清）：

```
底色亮度 = anim_color_level(底色)      // (r*3 + g*6 + b)/10，0 ~ 255
底色亮度 < ANIM_METEOR_BRIGHT_BG_LEVEL(224)：头 = 流星色（流星色太暗就用白）、尾 = 黑
底色亮度 ≥ 224（白底）              ：反过来，头 = 黑、尾 = 白
拖尾 = color_blend(尾色, 头色, 亮度档)
```

> 为什么：拖尾以前是在「底色 ↔ 流星色」之间渐变，青底 / 粉底 + 白流星时两边都很亮，
> 整条灯带都发白，看不出流星在哪。改成「流星色 → 黑」后，亮底上尾巴是黑的，一眼就能看到；
> 白底则反过来用「黑头 → 白尾」，否则白流星在白底上根本看不见。
> app 下发的底色本身不改（只用来判断亮 / 暗）。

### 2.10 流星雨 0x0A — `anim_meteor_shower`

| 项 | 内容 |
| --- | --- |
| 参数 | 颜色数量、颜色池、底色 |
| 状态 | 文件静态 `anim_meteor_head_pos[]` / `count` / `color_index` / `inited` |
| 内部宏 | `ANIM_METEOR_SHOWER_RATE_MAX`(17) / `ANIM_METEOR_SHOWER_FRAME_DIV`(3) / `..._MS_MIN`(10) |

**效果**：

```
拖尾长度 tail_len   = min(灯带长度, 17)          // 固定，不随颜色数量变
跑道   track_len    = 灯带长度 + tail_len
放得下（颜色数 * 拖尾长 <= 跑道）→ 同时跑「颜色数」颗，每颗一种颜色
放不下                          → 一次只跑一颗，跑完整条跑道再换下一个颜色（顺序跑完所有颜色）
每颗：头部最亮、越往后越暗（查 17 档亮度表，表尾的 0 表示不点亮）
每颗用自己的拖尾端点色（anim_meteor_trail_colors()：普通底「流星色→黑」、亮底「黑→白」）
帧间隔 = 流星动画的 1/3（最快 10ms），所以流星出现得更频繁
```

> 6 灯：拖尾 6、跑道 12 → **≤ 2 种颜色时同时跑，3 种及以上就是一颗一颗顺序跑**。
> 几颗流星颜色不同时，每颗都按自己的颜色算拖尾端点色，不会因为底色亮就一起看不见。

### 2.11 开合 0x0B — `anim_open_close`

| 项 | 内容 |
| --- | --- |
| 参数 | 颜色数量、颜色池、底色、**方向**（dir=0 开幕 / dir=1 闭幕）；**不用 app 的「多少个灯为一组」** |
| 状态 | `step` = 已经推进的灯数（0 ~ `_seg_len`）；`aux_param` = 本轮颜色下标；`aux_param3` = 停留帧计数 |
| 内部宏 | `ANIM_OPEN_CLOSE_WALK_SLOW_MS`(2400)、`..._WALK_FAST_MS`(800)、`..._FRAME_MS_MIN`(10) |

**节奏（一趟的时长只由速度决定，跟灯带长度无关）**：

```
walk_ms   = 速度在 [2400ms(0%), 800ms(100%)] 之间插值        // 一趟 = 从一端走到另一端
frames_max = walk_ms / ANIM_OPEN_CLOSE_FRAME_MS_MIN(10ms)    // 一趟最多这么多帧
step      = ceil(灯带长度 / frames_max)      // 每帧推进几个灯（6 灯 = 1 个灯/帧）
frames    = ceil(灯带长度 / step)            // 一趟的帧数 = 停留帧数
frame_ms  = walk_ms / frames                 // 帧间隔（≥ 10ms），返回给 WS2812FX
一轮 = 一趟 + 停一拍（+ 开幕收尾的 1 帧全灭）
```

> 为什么要这样算：帧间隔如果直接跟速度百分比走（最快 10ms），6 个灯一趟只有几帧，
> 一轮一百多毫秒，看起来就是整条灯带在闪。现在固定「一趟 800ms（最快）」：
> 灯带短 → 帧间隔自动变大（6 灯最快 = 133ms/帧）；灯带长 → 每帧多走几个灯；
> **一趟的时长始终不变**，所以灯带长短都不会闪。

**效果**：整条同色（颜色池里的当前颜色）。dir 在本模式下只用来区分开幕/闭幕，
亮区按逻辑位置画（不跟方向翻转）。

| dir | 表现 |
| --- | --- |
| 0 开幕 | 亮区 = `[0, progress)`：从逻辑 0 端（控制板那端）**流水式逐个点亮**到另一端（全灭 → 全亮）；全亮停一拍 → 整条熄灭（1 帧）→ 换色后从同一端重新点亮，循环 |
| 1 闭幕 | 亮区 = `[0, _seg_len - progress)`：以**整条点亮**开始，**从尾部（远离控制板那端）往回逐渐熄灭**（全亮 → 全灭）；全灭停一拍 → 换色后重新整条点亮，循环 |

- 每轮（开/闭各一次完整动作）结束时 `aux_param`（颜色下标）+1，颜色池循环取色，并 `SET_CYCLE`。

### 2.12 跑动 0x0C — `anim_run`

| 项 | 内容 |
| --- | --- |
| 参数 | **段大小 → 一组多少个灯（点宽）**、颜色数量、颜色池、底色、方向 |
| 状态 | `step` = 图案相位（0 ~ `unit` - 1）；`aux_param` = 点的颜色偏移（每跑完一圈 +1） |
| 内部宏 | `ANIM_RUN_GROUP_DIV`(3)、`ANIM_RUN_ROUND_SLOW_MS`(2000) / `..._FAST_MS`(500) / `..._FRAME_MS_MIN`(10) |

**「点 + 间隔」为一组**：一组 = 点宽个灯亮 + **同样多的**底色灯 → `unit = 点宽 * 2`

**点宽（一组多少个灯，`anim_run_group_len()`）**：

```
点宽 = app 下发的 byte7
     ├─ byte7 = 0（app 没指定）→ 按灯带长度自动分组：点宽 = 灯带长度 / ANIM_RUN_GROUP_DIV(3)
     └─ byte7 非 0            → 点宽 = byte7
点宽最少 1 个灯、最多 灯带长度 / 2（超了就整条灯带都是点，看不出间隔）
```

```
6 灯（本工程，byte7 = 0）-> 点宽 2：图案 ● ● ○ ○ ● ●（一组 2 亮 + 2 底色）
                            下一帧 ○ ● ● ○ ○ ●，再下一帧 ○ ○ ● ● ○ ○（整组沿灯带逐格推进）
12 灯                    -> 点宽 4：图案 ● ● ● ● ○ ○ ○ ○ ● ● ● ●
只有 3 个灯             -> 点宽 1（灯带越短，一组灯越少）
```

**节奏（跑完整条灯带的时长只由速度决定，跟灯带长度无关）**：

```
round_ms   = 速度在 [2000ms(0%), 500ms(100%)] 之间插值      // 跑完整条灯带
frames_max = round_ms / ANIM_RUN_FRAME_MS_MIN(10ms)         // 最多多少帧
step       = ceil(灯带长度 / frames_max)，再夹到 ≤ unit（一个「点 + 间隔」，否则点会被跳过）
frames     = ceil(灯带长度 / step)
frame_ms   = round_ms / frames（≥ 10ms）——直接作为动画函数的返回值
每帧相位 += step（不再固定 +1）
```

> 以前帧间隔直接跟 app 速度走（最快 10ms），6 个灯上「点 + 间隔」一个周期只有 2 帧 = 20ms，
> 肉眼看就是常亮 / 闪。现在：6 灯最快 = 83ms/格（周期 166ms），长灯带每帧多走几个灯，
> 跑完一整条仍然是 500ms（最快）~ 2000ms（最慢）。

**一帧画什么**（`anim_run_draw()`）：

```
一个「点 + 间隔」的宽度 unit = 点宽 * 2（点 + 同样多的底色）
一个完整配色循环的宽度 pattern_base = 颜色数量 * unit
第 i 个灯：图案下标 = i + pattern_base - 相位%pattern_base
          落在点上（图案下标 % unit < 点宽）→ 颜色 = colors[(图案下标/unit) % 颜色数量]
          否则                              → 底色
每帧相位 += step，走满 unit 算一轮（SET_CYCLE）
```

> 点的颜色按「点序号 + 颜色偏移」在颜色池里循环 → **只有 1 种颜色就是单色点跑动；
> 有多种颜色时，多个颜色的点同时跑，并且每跑完一圈颜色偏移 +1 → 点的颜色按颜色池依次流动**
> （贴近重构前的 `multi_dot_running`）。
> 方向：点沿逻辑位置前进，反向时用 `anim_led_index_of_dir()` 把下标反过来。

### 2.13 跑动集合 0x0D — `anim_run_collection`

| 项 | 内容 |
| --- | --- |
| 参数 | **只用速度 / 亮度**（配色、方向都写死在内置表里，不读 app 的颜色池） |

## 3. 声控动画（4 个）

### 3.0 声控的公共约定

| 项 | 说明 |
| --- | --- |
| 启动方式 | app 下发的声控模式索引 = `fc_effect.music.m`，由 `led_strip_rgb_scene_sound_apply()` 查表启动；越界（≥ 4）退化为第 0 个（能量） |
| 帧间隔 | **固定 `ANIM_SOUND_FRAME_MS`(20ms)**，**不跟 app 的动画速度**（声控要跟得上声音；跟着“往往最慢”的动画速度走就变成一两秒才动一下）<br>例外：节奏用自己的 `ANIM_SOUND_RHYTHM_FRAME_MS`(40ms) |
| 配色 | **完全不用 app 的颜色池/底色**，自己维护一张 3 色随机调色板（`ANIM_SOUND_COLOR_NUM` = 3）：颜色取色环上的随机位置，相邻两种至少隔 `ANIM_SOUND_HUE_GAP`(85)，保证分得开；每 20 帧(有声) / 100 帧(无声) 重新随机一次 → 看起来是「换色」而不是「闪」；「暗」固定用黑色（`anim_sound_off_color()`） |
| 声音强度 | `led_strip_voice_get_level()`：0~100，**快起慢落**（检测到声音直接跳到当前强度；没有声音时每 10ms 减 4，约 0.25s 归零） |
| 声音「一拍」 | `get_sound_triggered_by_led_strip_rgb()`：**读后自动清零，每帧只能读一次**；判定门限 `SOUND_BEAT_PERCENT`(15)（实测满音量强度只有 ~60，取 15 比较合适） |
| 满格校准 | `ANIM_SOUND_LEVEL_FULL`(60)：强度到 60 就算满格再映射成 0~255，否则能量条永远点不亮最后几个灯（调大 = 更迟钝） |
| 灯带长度 | 所有长度/位置都按 `_seg_len` 计算并夹紧，灯串少（6 灯）时也不会画到段外面 |

### 3.1 声控 0 · 能量 — `anim_sound_energy`

| 项 | 内容 |
| --- | --- |
| 参数 | 段大小（能量条的取色分组） |
| 状态 | `step` = 当前能量 0~255 |

```
目标能量 = 声音强度 / 60 * 255
起：目标 > 当前 → 立刻跳到目标（打击感）
落：目标 ≤ 当前 → 每帧减 (当前-目标)/4 + 1（平滑回落）
亮灯数 = 能量 * 灯带长度 / 255，边界那个灯按剩余能量渐变
颜色按段取色（段大小分组）→ 多色时能量条有层次
```

### 3.2 声控 1 · 节奏 — `anim_sound_rhythm`

| 项 | 内容 |
| --- | --- |
| 状态 | `step` = 这一拍已经打到第几个灯；`aux_param` = 当前颜色；`aux_param3` = 距上次起拍过了几帧 |
| 内部宏 | `..._FRAME_MS`(40) / `..._SPAN`(8) / `..._MIN_FRAMES`(6) / `..._IDLE_FRAMES`(15) |

```
拖尾长度 = 灯带长度 / 2（至少 1）
每帧推进 = max(1, 灯带长度 / 8)      // 6 灯 → 1 灯/帧
起拍条件：有声音 且（上一拍已打完 或 距上拍 ≥ 6 帧）；或者一直没有声音但已经隔够 15 帧（自动起一拍，灯带不会黑着）
头部最亮，身后按拖尾渐暗；每拍换一种颜色
```

### 3.3 声控 2 · 频谱 — `anim_sound_spectrum`

| 项 | 内容 |
| --- | --- |
| 参数 | 段大小（取色分组） |
| 状态 | 文件静态 `anim_spectrum_level[8]`（8 个频段的柱高） |
| 内部宏 | `..._BANDS`(8) / `..._DECAY`(6) / `..._IDLE`(12) |

```
灯珠位置 0..灯带长度-1 依次落在 8 个频段上（6 灯 = 每颗灯一个独立频段）
有声音：各频段在 [强度/2, 强度] 之间随机取高（柱子有高有低）
没声音：每帧 -6，掉到底保留 ANIM_SOUND_SPECTRUM_IDLE(12) 的底噪亮度（不会一片漆黑）
颜色按段取色
```

### 3.4 声控 3 · 滚动 — `anim_sound_scroll`

| 项 | 内容 |
| --- | --- |
| 参数 | 段大小（= 色块大小） |
| 状态 | `step` = 已经滚了多少格；`aux_param` = 还剩几帧加速 |
| 内部宏 | `..._SLOW_MS`(120) / `..._FAST_MS`(30) / `..._BOOST_FRAMES`(12) |

```
色块大小 = 段大小；如果只有 1 个灯 → 改成按颜色数量把灯带均分
          （例如 6 灯 + 3 色 = 每 2 灯一块），否则每个灯都在变颜色，看起来就是闪烁
没有声音：每 120ms 滚一格；检测到声音：每 30ms 滚一格并保持 12 帧，声音一停降回原速
一次只滚一格（多格跳 = 闪烁）；滚完「颜色数量 * 色块大小」格算一轮
方向：反向时把滚动量反过来
```
